Neural Composer is node-based compositing software for VFX and animation,
with machine learning built into the node graph. You key, roto, track, clean
up and grade the way you would in any compositor. SAM, ViTMatte, Stable
Diffusion, FLUX, depth estimation, upscaling and ComfyUI workflows are just
more nodes, and they work on the same scene-linear images as everything else.

I built it because, in most pipelines, the ML tools that are actually useful
in comp still live outside it. You export frames, run them through a notebook
or ComfyUI, and bring PNGs back. That loses linear float, the frame range and
any record of what was done. Here, a model's output is a matte or an image in
the graph, and it can be keyed, tracked, graded and rendered with the rest of
the shot.

The application is written in Python and Qt, with C++ kernels and OpenGL
where speed matters. Images are premultiplied `float32` in scene-linear
light. The interface follows Nuke's conventions, so a compositor can sit down
and use it straight away.

You click the object in the viewer, Ctrl-click anything to exclude, or drag a
box. With SAM 3 you can also type a short text prompt. SAM 2.1 or SAM 3 then
builds a Smart Mask layer and propagates it over the shot, in both directions
from the frame you marked. On the demo shot, SAM 2.1 reaches 0.963 IoU
against a hand-traced matte, compared with 0.891 for the built-in tracker.

An ML mask is rarely perfect, so the next steps are the ones a compositor
would take anyway:

- correct the boundary by hand;
- refine the edge band with ViTMatte in `MatteRefine`;
- convert the mask with *Segment → Bezier* into ordinary keyed Bezier shapes;
- track those shapes through the shot in the background, with an affine fit
  per shape.

The SAM model is also split into nodes: `LoadModel`, `ImageEncode`,
`MaskDecode` and `Prompts`. Each node is cached on its own inputs, so
dragging a prompt re-runs only the decoder. That takes 11 ms, against 103 ms
for the whole model.

## Keying

The keyers are ChromaKey with Despill, ImageKey against a clean plate,
CleanScreen, multi-sample ColorKey, RangeKey and EdgeExtend.

The ML part comes in for the edges. A rough key goes through `MatteRefine`.
ChromaKey then takes the refined matte back and subtracts the screen from the
mixed edge pixels. That keeps fine hair without a separate hand-built edge
key.

`Tracker2D` solves translation, rotation, similarity or a planar homography.
The track can drive a Transform, a Stabilize, or a CornerPin with four
editable perspective corners. *Create cleanup patch* builds the patch branch
from a tracked reference frame: paint, grade, mask and match-move. `Inpaint`
fills a removal mask from the surrounding pixels, or with SD 1.5 or SDXL
inside a bounded crop.

## Models

A Model Manager installs and verifies models, registers your own checkpoints
and A/B-tests two segmentation models on the same clicks. Inference runs in a
separate worker process, so the compositor itself never loads PyTorch.

The diffusion nodes cover SD 1.5, SDXL and FLUX.1 schnell, with LoRA,
ControlNet, image-to-image and inpainting. SDXL at 1024×768 with 25 steps
takes 9 s on an RTX 3080 Laptop GPU. Depth Anything V2 handles depth and
Real-ESRGAN handles upscaling. ComfyUI is supported in two ways: a node runs
a saved workflow on a ComfyUI server, or the server's node classes load
straight into the graph and are wired together with comp nodes.

Gaussian splats load as regular geometry. You can place them, animate them
with keyed transforms and cameras, combine them with meshes and render them
into the comp. The viewer sorts the whole cloud on the GPU, so a full frame of
the 1.5-million-splat strawberry draws in about 143 ms. While you orbit, a
point proxy keeps the viewer responsive. Selected splats can be deleted; the
edit is stored in a `SplatEdit` node, and the source file stays untouched.

The 3D side also reads Alembic, FBX, Maya ASCII, USD and OBJ. I wrote the
Alembic, FBX and Maya readers myself; against Maya 2020, vertex positions
match to within 1e-15.

## Agents

Project files are plain JSON. Anything the GUI renders can also be rendered
from the command line, and the result matches the GUI pixel for pixel. The
`analyze` command runs the same technical QC as the app and returns a
non-zero exit code when a check fails.

I use this with Claude Code and Codex. The agent gets a template graph and a
written shot workflow. It edits the project, renders and reads the QC report,
and then I review the shot in the GUI.

The project is in active development. The repository holds an overview for
now while I clean up the source for release.
