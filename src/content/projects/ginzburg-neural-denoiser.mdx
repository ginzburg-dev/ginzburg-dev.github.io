## The problem is motion, not the single frame

Path tracing estimates illumination from randomly sampled light paths. A smaller
sampling budget renders faster but leaves stochastic error in the image, and
that error resists naive filtering because sampling noise and fine scene detail
occupy the same high-frequency range. Filter too hard and the detail goes with
the noise.

Strong single-frame denoisers already exist. On a still frame Intel OIDN and
NVIDIA OptiX look excellent. The trouble starts when the sequence moves. A
denoiser that reconstructs each frame independently cannot enforce consistency
between frames, so residual noise and reconstruction error shift frame to frame.
A clip that looks clean when paused **boils and flickers** in playback.

STeR targets that directly: offline, high-quality denoising that stays stable
across a whole sequence, with no per-shot tuning at inference.

## STeR: Stable Temporal Restoration

STeR reconstructs the centre frame from a short temporal window, deciding per
pixel how much to trust each neighbouring frame and fusing them accordingly. It
can optionally take auxiliary render features such as albedo, normals and depth as
guidance where they exist. The noise level is estimated from the input, so an
artist sets no denoising strength and no temporal thresholds per shot.

## The dataset

The paired dataset was built from real production scenes. For each scene the
render was set up to produce one clean reference plus seven progressively
noisier variants on a render farm.

Samples are temporally contiguous rather than shuffled stills, so the data
carries real motion, occlusion, disocclusion, and changes in illumination and
scene content. Crop, flip and rotation parameters are sampled once per temporal
window, so augmentation never introduces frame-to-frame inconsistency that the
renderer did not produce. Beyond the paired data the pipeline can synthesise
Gaussian, Poisson-Gaussian, ISO-parameterised camera noise, residual patches
sampled from real footage, and Monte Carlo render noise, with the chosen profile
held constant inside each window.

## From checkpoint to runtime

The deployment runtime is written directly in C++ and CUDA against cuDNN and
cuBLAS, with custom FP16 kernels, memory-mapped weight files with lazy
host-to-device upload, RAII CUDA tensors, and deformable convolution through
im2col plus a cuBLAS GEMM. Motion compensation uses hierarchical block matching
with a coarse-to-fine pyramid and sub-pixel parabolic refinement, with DIS or
RAFT optical flow available as public backends.

Correctness is held to the Python reference by a parity harness that rejects any
maximum per-pixel difference above 0.005, backed by C++/CUDA unit tests, Python
tests, CLI integration tests and GPU CI.

## What is public, and what is not

The repository carries the data pipeline, reproducible public baselines,
evaluation, model export and the C++/CUDA runtime. STeR's architecture, training
recipe, calibration and weights stay private, as does the production dataset.
