Radiance4D is my real-time rendering engine for 3D Gaussian splats and
triangle meshes. It has native Direct3D 12 and Vulkan backends, and one set of
HLSL shaders compiles for both. A photogrammetry scan and a CG model can sit in
the same frame and occlude each other correctly.

I'm building it for three kinds of work:

- **Virtual production and VR.** A scanned location and CG elements have to
  render live, at a steady frame rate, from any camera.
- **AR and mixed reality.** CG has to sit convincingly inside a captured real
  space.
- **Synthetic data.** Rendering captured scenes from new viewpoints, with
  exact camera poses and depth, to produce training data for robots and
  autonomous vehicles.

The reference splatting code is CUDA, so it only runs on NVIDIA. This
pipeline is plain HLSL compute and runs on any Direct3D 12 or Vulkan GPU.

The project pulls together the two things I have worked on longest. One is
real-time rendering, from my own OpenGL engine to production work in Unreal
Engine. The other is temporal reconstruction, which is the same problem as
temporal denoising, approached from inside the renderer.

`.ply` files from the reference 3D Gaussian Splatting implementation load
directly, including degree-3 spherical harmonics and the conversion out of
COLMAP's coordinate frame. A small Python tool turns a COLMAP sparse model
into a `.ply` the engine can render.

## The splat pipeline

Every frame runs five GPU passes:

1. **Cull and project.** Each 3D covariance goes through the perspective
   Jacobian and becomes a screen-space ellipse. Spherical-harmonic colour is
   evaluated here, once per splat.
2. **Depth sort.** A GPU radix sort covers the whole scene. The key carries
   the full float depth, so the order is exact and the sort is stable.
3. **Tile binning.** The screen is split into 16×16 tiles. Splat–tile pairs
   are built in depth order and sorted by tile, so each tile's list stays
   depth-sorted without a second key.
4. **Tile rasterise.** One compute group runs per tile and one thread per
   pixel, front to back. A pixel stops as soon as it saturates.
5. **Composite.** Splats are blended over the mesh image, depth-tested per
   splat against what the mesh pass wrote.

## Meshes and shading

On Direct3D 12 the engine uses Enhanced Barriers, the retail Agility SDK and
DRED. On Vulkan it uses dynamic rendering and synchronization2. One vendored
DXC compiles every shader to both DXIL and SPIR-V at build time.

The tests run the splat pipeline on WARP, Microsoft's software rasteriser, so
they need no GPU. Image regression compares renders against stored
references, and a parity test holds the two backends to the same image within
1/255 per channel. Captures are deterministic: two runs of the same command
produce byte-identical images.
